Claude Code plugin

mg-harness

A durable Claude Code workflow for long-running, multi-session work.

Code is the easy part. The hard part is work that outlives a single context window — initiatives spanning dozens of chats. mg-harness is the harness for that: state files as the source of truth, planning and review subagents, and lifecycle hooks that keep an agent on-task across sessions. A handful of complementary skills cover the rest of a leader's job.

How an mg-harness session works

A single task, top to bottom. You drive the commands; the hooks, subagents, and state files work around them. Each step lists exactly what fires.

/start-workyou run it

Branches and seeds the four state files from templates — the scaffold for everything that follows.

⌘ /start-work creates plan.md creates state.md creates handoff.md creates CHANGELOG.md
2
/grillbefore planning · non-trivial

Interview one decision at a time to resolve the design before the planner drafts anything. Recommends an answer to each, explores the codebase to self-answer, and records settled decisions as durable state.

⌘ /grill writes state.md → ## Resolved decisions
3
planthe planner runs

The planner surveys the codebase and writes plan.md, honoring the resolved decisions — never relitigating them. No code without a plan.

🤖 planner writes plan.md reads state.md ◆ karpathy-coding-guidelines ◆ state-discipline
Every prompt drift-check.sh (UserPromptSubmit hook) re-injects the plan.md objective + open checklist items, so the agent can't quietly drift off the plan.
4
buildthe work loop

Work the checklist top-to-bottom. Every edit is bracketed by two hooks — a gate before, a log after.

◆ karpathy-coding-guidelines 🪝 verify-edit.sh — before each edit 🪝 post-edit-log.sh → CHANGELOG.md — after each edit 🤖 researcher — when a question needs digging
5
/checkpointevery 15–20 min

A lightweight save point: update the session state, summarize progress, commit. Nothing is lost.

⌘ /checkpoint updates state.md appends CHANGELOG.md ◆ state-discipline git commit
6
/verifybefore review

The quality gate: run the tests for real, audit the diff against the plan, then an independent review.

⌘ /verify runs test_command reads plan.md 🤖 reviewer ◆ karpathy-coding-guidelines (rubric)
7
/compactat ~50% context

Before context degrades, write a dense handoff a fresh session can read in 60 seconds, then reset. A hook also fires on automatic compaction, so nothing is lost if context fills first.

⌘ /compact writes handoff.md updates state.md appends CHANGELOG.md ◆ state-discipline 🪝 precompact-handoff.sh — also on auto-compaction git commit
8
/finish-worktask complete

One last verify, a final state + changelog summary, push, and an optional PR via the GitHub CLI.

⌘ /finish-work runs /verify 🤖 reviewer updates state.md appends CHANGELOG.md git push · gh PR
▸
Session endautomatic, on stop

Before the turn ends, a freshness check makes sure progress was actually saved.

🪝 checkpoint-freshness.sh — nudges /checkpoint if state is stale or changes are uncommitted
Files are the source of truth — not chat. Three of the hooks fire on their own the entire time: the plan is re-anchored on every prompt, and every edit is gated then logged. The conversation is disposable; the files persist.

The full inventory — each hook, command, subagent, state file, and skill, with exactly what sets it off. Nothing fires that isn't listed here.

Hooks — fire automatically, no command
load-state.shSession startReads state.md, plan.md, handoff.md & recent CHANGELOG.md and injects them into the opening context.
drift-check.shEvery user promptRe-injects the plan's objective + unchecked checklist items so the agent stays on-task.
verify-edit.shBefore each Edit/Write/MultiEditRuns your verify_command; blocks the edit (and feeds back the error) if the build is broken.

checkpoint-freshness.shOn stop / session endNudges you to /checkpoint if state.md is stale or there are uncommitted changes.

handoff.mdWritten at every /compactDense summary for the next session; re-injected by load-state on resume.

Why a harness, not just skills

mg-harness exists for one failure mode above all. The complementary skills each fix a narrower one.

THE REASON

Multi-session work loses state

The biggest work — strategy, migrations, multi-week initiatives — doesn't fit in one chat. You hit the context limit, stop for the day, and re-derive everything next time: what was decided, what failed, what's left. The harness makes that discipline automatic instead of relying on memory — state files, structured handoffs, drift detection, and a verification gate, all under the /mg-harness: namespace.

Complementary skills — narrower failure modes

The agent overbuilds

A small ask becomes a sprawling diff — adjacent code "improved," speculative abstractions added. Discipline loads before the first line is written.

karpathy-coding-guidelines

Triage eats your week

The mechanical half of triage is solved; the judgment half burns calendar time. This layers on top of Linear's native triage, not in place of it.

linear-triage-automation

Signal is scattered

Hundreds of unread items across Slack, Teams, and email. A scheduled task does the synthesis before you sit down each morning.

morning-briefing

Handoffs lose context

Reassigned tickets arrive with a one-line comment and the new owner pays the tax. Context becomes the precondition for reassignment.

Quickstart

Thirty seconds to install. Two optional config values unlock the verification hooks.

Add the marketplace & install

/plugin marketplace add mgrabovskyi/skills
/plugin install mg-harness@mg-harness

Configure the verification hooks (optional)

/plugin config mg-harness
# set verify_command  e.g. npm run lint --silent
# set test_command    e.g. npm test --silent

Start working

/mg-harness:start-work add JWT validation to the auth service
